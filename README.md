# Students Database CRUD Application

A Python backend for managing student records, built for the **EWB Edu Tech Internship Project Assignment**.

- **Core:** Create / Read / Update / Delete students with **FastAPI** and **SQLite** (data persists in a local `students.db` file).
- **Bonus (optional):** Ask natural-language questions about the data using a **local Ollama model**. The AI is grounded in records fetched by backend code and never runs SQL.

All sample data is **dummy data** (`@example.com` emails, fake phone numbers). No real personal information is included.

## Prerequisites

- Python **3.9+**
- (Optional, for the AI bonus) [Ollama](https://ollama.com/download)

## Installation

```bash
git clone <your-repo-url>
cd student-crud-api

python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

## Run

```bash
uvicorn app.main:app --reload
```

- API: http://127.0.0.1:8000
- **Interactive docs (Swagger UI): http://127.0.0.1:8000/docs**

The SQLite file `students.db` and the `students` table are created automatically on first start.

Optional: load 10 dummy students (safe to run repeatedly):

```bash
python seed.py
```

Use a different database file with an environment variable: `STUDENTS_DB_PATH=other.db`.

## Student fields

| Field | Required | Notes |
|---|---|---|
| `id` | auto | Unique integer, generated by the database |
| `name` | yes | 1-100 characters |
| `date_of_birth` | yes | `YYYY-MM-DD`, not in the future |
| `email` | one of email/phone | Valid format, unique, stored lowercase |
| `phone` | one of email/phone | 7-20 digits, may start with `+` |
| `course` | no | |
| `address` | no | |
| `enrollment_date` | no | `YYYY-MM-DD`, not before date of birth |

## API endpoints

| Method | Endpoint | Purpose | Success |
|---|---|---|---|
| POST | `/students` | Create a student | `201` |
| GET | `/students` | List / filter students | `200` |
| GET | `/students/{student_id}` | View one student | `200` |
| PUT | `/students/{student_id}` | Replace all details | `200` |
| PATCH | `/students/{student_id}` | Update only supplied fields | `200` |
| DELETE | `/students/{student_id}` | Delete a student | `204` |
| POST | `/ai/ask` | *(Optional)* Ask a question about the data | `200` |
| GET | `/health` | Health check | `200` |

**Error responses:** `404` student not found, `409` duplicate email, `422` validation error, `503` Ollama unavailable.

**List filters** (`GET /students`): `name` (contains), `course` (contains), `email` (exact), `born_after`, `born_before` (strict, `YYYY-MM-DD`), `limit` (1-100, default 20), `offset`. The total number of matches is returned in the `X-Total-Count` response header.

## Testing the API with curl

```bash
# Create
curl -X POST http://127.0.0.1:8000/students \
  -H "Content-Type: application/json" \
  -d '{"name":"Aarav Sharma","date_of_birth":"2004-03-15","email":"aarav.sharma@example.com","phone":"+91 90000 00001","course":"Python Backend Development","enrollment_date":"2024-07-01"}'

# List all / filter
curl http://127.0.0.1:8000/students
curl "http://127.0.0.1:8000/students?course=python&born_after=2003-12-31"

# Read one
curl http://127.0.0.1:8000/students/1

# Update (partial)
curl -X PATCH http://127.0.0.1:8000/students/1 \
  -H "Content-Type: application/json" -d '{"course":"Data Science"}'

# Update (full replace)
curl -X PUT http://127.0.0.1:8000/students/1 \
  -H "Content-Type: application/json" \
  -d '{"name":"Aarav Sharma","date_of_birth":"2004-03-15","email":"aarav.sharma@example.com"}'

# Delete
curl -X DELETE http://127.0.0.1:8000/students/1

# Missing record -> 404
curl -i http://127.0.0.1:8000/students/999
```

Or just use the **Try it out** buttons in `/docs`.

## Optional bonus: local AI with Ollama

1. Install Ollama and pull a small model:
   ```bash
   ollama pull llama3.2:1b
   ollama serve        # skip if the Ollama app is already running
   ```
2. Make sure the database has data (`python seed.py`), then ask:
   ```bash
   curl -X POST http://127.0.0.1:8000/ai/ask \
     -H "Content-Type: application/json" \
     -d '{"question":"How many students are there?"}'

   curl -X POST http://127.0.0.1:8000/ai/ask \
     -H "Content-Type: application/json" \
     -d '{"question":"List students born after 2005"}'
   ```

Settings (environment variables): `OLLAMA_MODEL` (default `llama3.2:1b`), `OLLAMA_HOST` (default `http://localhost:11434`), `OLLAMA_TIMEOUT` (seconds, default `120`).

### How it stays accurate and safe

1. **The model never touches SQL.** Backend code converts the question into a small set of fixed filters (course, birth-year range, student name) and runs **parameterized** queries.
2. **Retrieval first, then generation.** Only the retrieved records, plus exact counts computed in code (so a small model doesn't have to count), are sent to the model as context.
3. **Grounded prompt.** The model is instructed to answer only from that data, say so when the data can't answer, and ignore instructions hidden inside the data. Temperature is `0`.
4. **Minimal data sharing.** Email, phone and address are only included when the question asks for them. At most 50 records are sent.
5. **Transparent.** The response includes `filters_applied`, `total_matching` and `records_used` so every answer can be checked.

Supported question patterns include counts ("How many students are there?"), birth-year ranges ("born after 2005", "born in 2004", "born between 2003 and 2005", "born before 2004"), course questions ("How many take Data Science?") and student lookups ("What is Diya's email?"). Questions that need other logic get the full-database count and the first records, and the model will say if it can't answer.

## Design notes

- **Layers:** routes (`main.py`) -> validation (`schemas.py`) -> data access (`crud.py`) -> SQLite (`database.py`).
- **One short-lived SQLite connection per request** (FastAPI dependency), which is safe with FastAPI's threadpool.
- **Validation lives in one place** (`StudentCreate`). PATCH merges the changes onto the stored record and re-validates the result, so a partial update can't leave a student without contact info.
- **Constraints in the database too:** `UNIQUE(email)` and `CHECK(email IS NOT NULL OR phone IS NOT NULL)`.

## Security notes

- No secrets or real personal data in the repo; `.gitignore` excludes `.env` and `*.db`.
- All SQL uses bound parameters; `LIKE` wildcards in user input are escaped.
